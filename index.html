🧪 The 6 agentic evals what each metric needs and how it judges

      

        
EvalInformation requiredHow it judgesThreshold

        
          
Plan QualityUser input, the agent's plan and the execution traceIs the plan adequate, clear, complete and ordered?0.5

          
Plan AdherenceThe produced plan, tool calls and observed resultsDid the execution follow the original plan?0.5

          
Tool CorrectnessInput, output, tools_called, available tools and expected_toolsDid the agent pick the right tools, in the right order, for the right purpose?0.7

Step EfficiencyInput, trace, tool calls and resultsDid the agent use just enough steps, with no unnecessary calls?0.5

🧾 Engineering decisions ADR — the choices that hold the tool together

      

        
ADR-01
Vanilla SPA, zero backend
Pure HTML+JS — open, share and iterate with no infra. A real API comes later, without touching the screens.

        
ADR-02
Everything derives from the sources
every UI number comes from toqan_agents + toqan_interactions — nothing invented; a SQL query proves the origin.

        
ADR-03
LLM-as-judge on the eval pillar
relevance, faithfulness, plan and efficiency follow the DeepEval/RAGAS patterns of the iFood templates (scores on Langfuse).

        
ADR-04
Evolution by snapshot
every change becomes a new snapshot — the ranking re-confirms and evolution stays visible over time (diagram loop).

🧠 Como cada ferramenta funciona 3 papéis num único encanamento — sem decorar, é enxergar

      

        
GUARDA
🗄️ Databricks
os dados vivem aqui, em 3 camadas: bronze (cru) → silver (limpo) → gold (pronto)

        
→

        
ENTREGA
⚙️ FastAPI + 🔐 OAuth
o "waiter": a tela pede → busca no Databricks → devolve JSON. O porteiro confere o crachá.

        
→

        
MOSTRA
🎨 Telas do Prisma
o que você usa. Cada aba é uma janela do mesmo encanamento.

      

      
Dois motores auxiliares se plugam nesse encanamento: o 🧪 REVISOR (GenPlat dá nota · DeepEval/RAGAS fazem as perguntas · Langfuse guarda a caderneta) e a 🔀 MUDANÇA (GitLab abre o MR · humano aprova · Delta guarda a história).

      

        
🧠GenPlat🟢 usar
The rented brain at iFood: manda text, devolve text. 3 papéis: juiz (dá nota), escritor (gera receitas) e tradutor (text → vetor).

        
🧪DeepEval + RAGAS🟠 média
As provas: cada métrica faz UMA pergunta ao juiz ("a resposta é fiel?") e recebe nota 0–1 com justificativa. iFood já tem os templates.

        
📦Langfuse🟢 fácil
The notebook: stores every score with date and justification — this is where the agent evolution history comes from.

        
🔀GitLab + MR🟢 fácil
The approval mail: Prisma proposes the change (MR); the agent owner approves; only then it goes live. Nothing changes without a human.

        
🧬Embeddings + pgvector🔴 alta
The star map: text becomes a coordinate; the question becomes a point; the closest agents are the right ones. This is the "Find the Agent" GPS.

        
📸Delta + Datadog + Slack🟢 fácil
Ledger + siren: Delta stores every score version; the daily job compares and, if it worsened, the alarm lands on the team Slack.

      

      

        💡 Regra de ouro:
        nenhuma ferramenta aqui é tecnologia nova — a iFood já usa todas. O trabalho do Prisma é ligá-las em sequência. Complexidade real: só calibrar o juiz e a busca por similarity (marcados em 🔴).
      

    


    

      

        
👥 Quem faz o quê uma linha por área
    

      
🧪 Exemplo de ponta a ponta a técnica funcionando, com um agente real deste protótipo: 🖋️ ETL Scribe (nota 12)

      
      

        
1. The system reads the agent from the registry — like opening its file.

        
2. The engine computes the 16 criteria and reaches 12/100.

        
3. The automatic judge (GenPlat) evaluates its answers and points where it fails.

        
4. The Ranking shows: #11 of 11, idle, with a governance alert.

        
5. The recipe engine generates the corrected prompt — before × after side by side.

        
6. The simulation shows the predicted score: 12 → 78. It only proceeds if it improves.

        
7. The system opens the merge request on GitLab — the agent owner approves.

        
8. The improvement lands in history and the daily job confirms (or alerts) the new score.

      

      
💡 This is how the 6 steps become 1 continuous flow: Steps 1–2 feed nodes 1–4, Steps 3–5 become nodes 5–8, and Step 6 is the green loop — everything runs on its own, with a human only where it matters (node 7).
